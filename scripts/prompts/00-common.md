## この試験に固有の 3 つの要求

### 1. 数式を出さない

**この試験に数式は出ません。** 公式シラバスの詳細キーワード約 200 語を端から確かめて、数式を要求する項目は 1 つもありませんでした。

**本文に `$...$` を書かないでください。** 仕組みは図とたとえ話で説明します。
数式を書きたくなったら、**たいてい説明が技術寄りに寄りすぎています。**書き方のほうを直してください。

### 2. 英略語は「3 点セット」で書く

**この試験の最大の得点源であり、最大のつまずきどころです。**

英略語を**初めて出したその場で**、次の 3 つを必ず書いてください。

1. **正式名称**（例：Retrieval-Augmented Generation）
2. **訳**（例：検索拡張生成）
3. **何をするものか**（例：手元の資料を検索してから答えさせる仕組み）

入門編の [略語とカタカナ語の読み方](textbook/i-3) に一覧があります。**そこに載っている略語も、本文の初出では 3 点セットで書き直してください。**辞典を引かずに読み進められることが大事です。

**とくに紛らわしい組は、本文で並べて対比してください。**

- **AGI の G は General（汎用の）**、**GAN・GPT の G は Generative（生成する）**
- **N は Network・Narrow・Natural の 3 つ**、**R は Recurrent・Reinforcement・Retrieval の 3 つ**
- **LM（言語モデル）／LLM（大規模言語モデル）／MLM（穴埋めさせる学習のしかた）** は別物

### 3. モデル名・サービス名には「いつ時点の話か」を書く

**第 2 章・第 3 章は半年で古くなります。**

- **モデル名・性能・「できること」に触れるときは、「いつ時点の記述か」を本文に必ず書いてください。**
- 「現在最も高性能な」のような、**時点を書かない最上級の表現は使わないでください。**
- **モデル名・サービス名は「何ができるようになったか」とセットで書いてください。** 名前だけ並べても覚えられません
- 確定していない論点は**断定しないでください。**「〜と解されている」「〜が論点になっている」と書きます

## 一問一答は厚めに

**本番は 60 問を 60 分（1 問ちょうど 60 秒）で解く試験です。** 考えて解くのではなく、用語を即座に思い出せるかが問われます。**この試験は用語の取り違えで落とすので、一問一答が対策そのものになります。**

各節の末尾に、次の形で **5 問以上**（できれば 6〜8 問）置いてください。

- 1 行 1 問。`問い :: 答え` の形
- 問いも答えも 1 行に収める（改行しない）
- 答えは、その場で声に出して言える長さにする
- **問いの中に `::` を使わない**
- **英略語の正式名称は一問一答向きです。**「RAG の正式名称と訳は :: Retrieval-Augmented Generation、検索拡張生成です」の形を厚めに入れてください

## 記法（Markdown サブセット）

### 図

```` ```diagram:種類 ```` で図を書けます。使える種類は `flow` `stack` `tree` `matrix` `cycle` `seq` `bits` `compare` の 8 つです。

- `キー: 値` の行は指示子（`title` `top` `bottom` `x` `y` `note` `actors` `caption`）
- それ以外の行が要素。`ラベル :: 補足` で**補足**を付けられる
- `tree` はインデント 2 スペースで 1 段のネスト
- `stack` は**先頭が最も幅広い**。上下の向きが意味と合っているか確かめること
- **図の中では `**強調**` が効きません。** アスタリスクがそのまま画面に出ます
- **図の題に「N つ」と書いたら、要素の数を N 個に合わせてください。** 検査が数えます

#### `compare` の書き方（**系譜で 4 回壊しています**）

`compare` は **「1 行 1 セル、偶数行が左・奇数行が右」**です。**`::` は左右の区切りではありません。**

正しい書き方：

```
title: 学習と推論
actors: 学習 | 推論
モデルを作る場面
できたモデルを使う場面
時間も費用もかかる
一瞬で終わる
```

**やってはいけない書き方**（`::` は補足であって左右の区切りではないので、意味が壊れます）：

```
モデルを作る場面 :: できたモデルを使う場面
```

**要素の数が偶数だと検査を素通りします。**書いたあと、左右が正しく対になっているか目で確かめてください。

**図は「本文で説明したことを整理する」ために使ってください。** 図に本文と違うことを書かないこと（姉妹アプリで実際に食い違いが出ました）。
**本文からソースの行番号を指さないでください。**「最大の問題は 3 行目です」のような書き方は、`compare` が左右に振り分けられるため読者の画面と合いません。
