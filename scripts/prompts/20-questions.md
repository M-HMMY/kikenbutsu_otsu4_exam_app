
- **`source` は設定しないでください。** 実際の試験問題は非公開なので、すべてオリジナルの練習問題です

## 守ること

### 問題文

- **空白を除いて 120 字以内。** `npm run check` が 120 字で注意、160 字でエラーにします。**1 問 60 秒で読める長さに**
- **問題文の中に答えを書かないこと**
- **教本に書かれていることだけを問うこと。** 教本にない事項を問わない
- **時点で変わる事柄を問わないこと。**「最も高性能なモデルはどれか」のような問題は作らないでください。**モデル名を問うなら「何を作るものか」「どこが提供しているか」**にすること

### 選択肢

- **4 つ。重複させない**
- **正解の位置を散らすこと。** 姉妹アプリでは「エ」が 288 問中 3 問だったことがあります。**書き終えたら、ア・イ・ウ・エ の数を自分で数えて、報告に書いてください**
- **誤答も正解と同じ密度で書くこと。** **正解だけが長いと、読まずに「長いものを選ぶ」で当てられます。**4 つの長さをそろえてください
- **「必ず」「すべて」「常に」「一切」を誤答専用にしないこと。** 言い切りが誤答側にしか出てこないと、それ自体が手掛かりになります。**正解の選択肢にも、正しく言い切れる場面では使ってください**
- **誤答は「もっともらしい」ものにすること。** 同じ章に出てくる別の用語を使うのが基本です（CNN の問題の誤答に RNN・LSTM・Transformer を置く、など）
- **分類の軸を混ぜないこと。** 4 つの選択肢が、同じ軸の上に並んでいること。別の軸の言葉を混ぜると、両方成り立ってしまいます

### 解説

- **正解の理由だけでなく、誤答がなぜ誤りかにも触れること。** **4 つすべてに触れてください。**「誤答の説明もれ」は系譜で最も多い型です
- **かっこ書きで言い換えを添えるときは、本当に同義語か確かめること。** 別の意味の専門用語を添えてしまった例があります
- **語源を書くときは思い込みで書かないこと**
- 解説の内容が、**教本の該当節と食い違わないこと**

### 章をまたいだ重複

- **同じことを問う問題を、別の節で作らないこと。** `npm run check` が、選択肢まで含めた類似度で検出します
- **担当章の中でも、対比のために対で作る場合を除いて、似た問題を並べないでください**

## この試験に効く出題の型

**用語の取り違えで落とす試験なので、次の型を厚めに入れてください。**

1. **英略語の正式名称を問う** … 「RAG の正式名称として適切なものはどれか」。**選択肢に似た略語の正式名称を並べる。**この型は確実に出ます
2. **役割の取り違えを突く** … 「GAN において、本物か偽物かを見破る役割を担うのはどれか」
3. **似た用語の区別** … 「要配慮個人情報の説明として適切なものはどれか」（誤答に個人識別符号・匿名加工情報の説明を置く）
4. **どの文書のものかを問う** … 「AI 事業者ガイドラインの共通の指針に含まれ、AI 社会原則には含まれないものはどれか」。**この場合、必ず「どの文書の話か」を問題文に明示してください。**書かないと答えが定まりません
5. **「当てはまらないもの」を問う** … 適切でないものを選ばせる形。**「適切でないもの」を太字や強調ではなく、文としてはっきり書いてください**
6. **仕組みから理由を問う** … 「テキスト生成 AI が正確な文字数の指定を苦手とする理由として適切なものはどれか」

## バックスラッシュの落とし穴

TypeScript の文字列の中に書くので、次のエスケープが要ります。

| 書きたいもの | ファイルに書く形 |
| --- | --- |
| `\n` を文字として出す | `\\n` |
| バッククォート（テンプレートリテラル内） | バックスラッシュ + バッククォート |
| `$` + `{`（テンプレートリテラル内） | バックスラッシュ + `$` + `{` |

**bash のヒアドキュメント（`cat > file <<'EOF'`）は使わないでください。** バックスラッシュが落ちます。
ファイルの編集は、エディタ相当の書き込み（apply_patch 等）で行ってください。
